## 2. ANÁLISIS PROFUNDO POR PROYECTO

### 2.1 OPENHAVEN — Navegador de Convergencia

#### Arquitectura de Datos (Matrix Beta)
- **205 entradas** con **40+ atributos estandarizados** cada una
- **Navegación:** Casos de Uso → Capacidades → Herramientas (no tech-first)
- **Atributos clave:** Gobernanza (Fundación/Comunidad/Empresa/Estándar), Riesgo de Captura (Mínimo→Alto 1-11), Tipo Entidad, Estado Desarrollo, last_investigated
- **Ejemplos entradas clave:** ActivityPub (Estándar Abierto, Riesgo Mínimo2, Final), ERC-8004 (Estándar Abierto, Riesgo Bajo2, Borrador), Holochain (Fundación, Moderado11, Activo), First Person Project (Comunidad, Mínimo3, En desarrollo)

#### Gobernanza y Verificación (Proceso)
```
Investigación Activa → Envíos Comunidad → Revisión Líder Investigación 
  → Confirmación Equipo Desarrollo → Verificación Terceros (N) 
  → Señales aditivas (no secuenciales)
```
- **No etiquetas "verificado/no verificado"** → señales independientes aditivas
- **last_investigated** por entrada → datos desactualizados visibles
- **Riesgo de captura** = estructura gobernanza observable (aún en definición)

#### Diferenciadores Clave para HSCSG/Gaia
1. **Interoperabilidad de protocolos informada por interoperabilidad social** → alineado con "Vasos Comunicantes" HSCSG
2. **Navegación Casos de Uso → Capacidades → Herramientas** → mapea directo a CoachFAB + navteka UX
3. **Construido para flujos IA** → `llms-full.txt` + prompts para stacks → alineado con Hermes Agent
4. **Conector, no plataforma** → apunta a comunidades existentes → principio "Vasos Comunicantes"
5. **Voz colectiva** → hogar compartido para movimiento → alineado con "Alianza de Interdependencias y Autonomías"

#### APIs y Datos Accesibles
- ✅ `llms-full.txt` → corpus completo normalizado (patrón GitBook)
- ✅ `llms.txt` → índice/TOC ligero
- ✅ `sitemap.xml` → grafo de páginas
- ❌ API formal documentada → pero matriz HTML parseable
- **Matrix URL:** `https://openhaven.net/es/prototype/matrix` (205 filas, filtrable)

#### Modelo de Contribución
- Formulario estructurado: nombre, gobernanza, capacidades, estado, referencias
- Atribución obligatoria → crédito en tarjetas del Navegador
- Vías gobernanza abriéndose progresivamente

### 2.2 PROJECT WEAVE — Capa 3: Community Trust

#### Pila de Protocolos (Stack Weave)
| Capa | Protocolo | Estado | Función |
|------|-----------|--------|---------|
| **Anchor** | FPP (First Person Project) | Maduro, active standards | Personhood credentials sin wallets/blockchain |
| **Groups** | Groups as first-class objects | Stream C deliverable | Grupos como primitivas protocolo (membership, governance, trust signals) |
| **Trust Graph** | DTG (Decentralized Trust Graph) | Diseño | Trust portable across communities sin merge governance |
| **Communication** | TSP (Trust Spanning Protocol) | Diseño | Messaging soberano, resistente a censura/vigilancia |
| **Bridging** | Adapters (KERI/ACDC, did:webvh, etc) | Conectivo | Conective tissue entre estándares existentes |

#### Insight Clave: Community Formation ≠ Governance Tools
> "The trust protocols are not governance tools. They are **community-formation infrastructure** that generates governance capacity as a downstream consequence."

**Flujo:** Personhood → Groups as primitives → Portable trust → Secure comms → Communities form → Governance follows

#### Patrones de Captura que Diseñan Contra
| Patrón | Defensa Weave |
|--------|---------------|
| Platform capture | Protocols not platforms (open standards, no owner) |
| Winner-picking | Functional plurality (múltiples implementaciones) |
| Architecture lock-in | Interoperability non-negotiable; architecture agnostic |
| Certification regime | Shared test harness (verifiable behavior, not permission) |
| Custodianship | No data/identity/relationships held |

#### Landscape Analysis — What's Missing
| Categoría | Problema | Qué Weave Construye |
|-----------|----------|---------------------|
| Ecological credit | Blockchain wallets + property docs → excluye stewards | Personhood sin wallets |
| Public goods funding | Crypto-native presupposition, no personhood | Community vouching (relationship-based) |
| Community coordination | Manual trust no escala across boundaries | Groups as first-class protocol objects |
| **Gap universal** | **Skip trust layer, bolt on later badly** | **Trust layer FIRST** |

#### Capital Architecture: 6 Streams Paralelos
| Stream | Función | Modelo |
|--------|---------|--------|
| **A · Fellowship** | Estabilizar builders en vuelo | Stipends peer-nominated, 18mo depreciation |
| **B · Protocol Implementation** | Build substrate | Contracts (not grants), final payment on interop tests |
| **C · Groups Cohort** | Build missing protocol layer | Dedicated cohort: spec + ref impl + interop test suite |
| **D · Canal Funds** | Growth capital no extractivo | Zebra model: "canals not moats", 5-20% returns |
| **E · Technical Convening** | Neutral ground | Project Weave as convenor (Kaliya/Kevin) |
| **F · Ecosystem Grants** | Adoption + UX | Real-world adoption, cross-project bridges |

#### Three Paths (Futures)
1. **Surveillance** (Control) → Threads pull
2. **Collapse** (Chaos) → Threads break  
3. **Regeneration** (Agency) → Threads woven, in our hands

**Weave works with all three** — infraestructura resiliente para cualquier futuro.
