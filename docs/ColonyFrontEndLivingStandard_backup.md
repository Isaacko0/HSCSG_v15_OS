## Qué es
Un **living standard** de principios y guías para balancear velocidad, consistencia y calidad al desarrollar el frontend de Colony. Es una referencia de buenas prácticas (no un paquete instalable).

### Principios documentados (relevantes para HSCSG)
- Consistencia de estándares entre devs nuevos y viejos.
- Velocidad sin sacrificar calidad.
- Documentar el estado actual de mejores prácticas.
- Mejorar vía PR/issue (gobernanza abierta del estándar).

### Lo que aporta a HSCSG
| Principio | Mapeo HSCSG |
|-----------|-------------|
| Estándar vivo de frontend | **HSCSG Technical Standards** (de OneManCompany): SSOT, TDD, Registry, No-silent-exceptions |
| Consistencia entre devs | `ui-components.md` (inventario de componentes) ya en skill repo-assimilation |
| Gobernanza del estándar por PR | CDS (consentimiento) para cambios de arquitectura |
| Calidad + velocidad | Vessel+Talent (arquitectura agéntica) + E²R Tree Search |

### Qué ASIMILAR
- **Adoptar como referencia de UX de gobernanza**: cómo Colony presenta dominios, tesorería y votación al usuario final → alimenta la pantalla `/colectivo` y el módulo **CDS** de HSCSG.
- **Principio de "estándar vivo"** → el BRIEF y las skills HSCSG se mantienen igual (documentación viva, versionada en GitHub).
- No requiere código: es una guía declarativa (como Mundus/Civilizaciones).
